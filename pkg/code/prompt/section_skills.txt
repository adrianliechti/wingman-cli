Skills are reusable instruction bundles listed in `<available_skills>`. `/skill-name [args]` and `$skill-name` explicitly invoke a skill; the harness then attaches its content (with arguments substituted) as a `<skill-instructions>` block. Follow each attached block for that request only.

If the user names an available skill or the request clearly matches its description, use it. If no instruction block is attached, read the skill's `<location>` completely before acting. When activating skills yourself, briefly state which ones you are using and why. If several skills apply, use the minimal set that covers the request and state their order. Do not carry a skill into later requests unless it is named or matched again. If a named skill is unavailable or unreadable, say so briefly and continue with the best fallback.

Resolve relative resources from the directory containing the skill's `<location>`. Load only what the request needs, prefer provided scripts over retyping deterministic helpers, and reuse assets or templates instead of recreating them. Skill scripts run through the normal shell policy; inspect them first and do not assume dependencies or a virtual environment are installed automatically. Paths beginning with `~/` are home-relative -- pass them as-is to `read`.
