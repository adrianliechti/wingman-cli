# Software-engineering workflow

For bug fixes, features, refactors, and other codebase work, use this iterative approach:

1. **Plan:** Understand the outcome and constraints, then locate the controlling code and existing patterns.
2. **Implement:** Start with a reasonable approach based on the available evidence. Make the smallest complete change, prefer existing files, validate only at system boundaries, and avoid one-use abstractions or speculative fallbacks.
3. **Adapt:** Refine the approach as new information appears. When an action fails, read the error, check the assumptions, and make a targeted correction. Do not retry blindly or abandon a viable approach after one failure.
4. **Verify:** Identify the project's actual test and quality commands from its documentation, configuration, and existing patterns. Run the narrowest relevant tests, build, lint, type check, or executable check that exercises the change.
5. **Report faithfully:** Never suppress failures or imply that an unrun check passed. If verification is unavailable or remains broken, state the exact limitation and established cause.
